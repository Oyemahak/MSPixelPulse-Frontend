# Revision Agent

## Brand and protected structure

- MSPixelPulse is a Toronto website agency. Public business data comes from `src/data/site.js`; demo placeholders are used only in demo projects.
- Demo-only placeholders are `hello@mspixelpulse.com`, `+1 (000) 000-0000`, and `#` for social links.
- Public pages are home, projects, services, pricing, contact, blog, about, legal, authentication, and protected portals.
- Preserve the shared header, footer, theme, route structure, portal security boundaries, blog category model, top-10 ranking, and progressive loading.
- Do not edit unrelated repos or `Oyemahak/Katrina-Studios`.

## Revision checklist

- Confirm the page's audience, search intent, customer task, and business purpose.
- Improve clarity, evidence, structure, tone, and usefulness before changing style.
- Remove unsupported claims, invented proof, keyword repetition, vague filler, fake urgency, and duplicate sections.
- Verify source links, dates, local details, image attribution, alt text, internal links, metadata, and calls to action.
- For AI-assisted posts, keep the disclosure accurate and never imply human expert review that did not occur.
- For Ontario accessibility or Canadian privacy topics, retain the general-information limitation and verify current official guidance.

## Blog safety

- Never bulk-promote `content/blog-drafts.json` into `publishedBlogPosts`.
- Reject near-duplicate city or industry doorway pages.
- Preserve unique cover assignments; no two published articles should use the same cover URL.
- Confirm a revised article is substantially complete and useful before it enters the sitemap.

## Quality and release

- Check light and dark themes, keyboard use, visible focus, 44px targets, reduced motion, mobile overflow, headings, and contrast.
- Run lint and production build after code or data changes.
- Review sitemap count, static metadata generation, route rendering, and an individual article.
- Commit and push only after successful checks. Do not trigger production deployment unless explicitly requested.
- Maintain reusable data/components and update agent knowledge when a verified publishing or UI decision changes.
- Portal revisions must preserve the shared 400–600 typography hierarchy, central notification components, explicit read state, role-specific deep links, dedicated payment endpoint, and retained receipt/void audit history.
